# Dungeon Dogfood: Building a Game with the Engine

## 1. Introduction: The "Dogfooding" Philosophy
"Eating your own dogfood" is a term used in software development where a company uses its own products to validate them. 

**`dungeon_dogfood`** exists to answer one question: "Is this engine actually fun and easy to use?" 
-   If it takes 500 lines of code to move a player, the engine API is too complex.
-   If the game stutters when a door opens, the engine's loading logic is broken.

This app is a simple 3D dungeon crawler that stresses every system in the engine.

---

## 2. The Application Architecture

The app is built using a simple "State-driven" architecture. It is NOT an ECS (Entity Component System), but a clean, procedural approach that is easy for students to follow.

### 2.1 The `GameState` Struct
This is the "Source of Truth" for the entire game.
```rust
pub struct GameState {
    pub player: Player,
    pub dungeon: DungeonLayout,
    pub entities: Vec<Entity>,
    pub frame_timer: Timer,
}
```

## 3. Detailed Logic: Player Movement (`player.rs`)

### 3.1 Input Handling
The `Player` struct implements the `KeyboardListener` trait from the `input` module.
-   **Logic**: We don't "move" when a key is pressed. We just set a **Boolean Flag** (e.g., `is_moving_forward = true`).

### 3.2 Delta-Time Integration
Your computer might run at 60 FPS, but a student's laptop might run at 30 FPS.
`NewPos = CurrentPos + (Direction * Speed * DeltaTime)`

## 4. The Dungeon Generation Algorithm: Random Walk

How do we create the dungeon? We use a **Random Walk** algorithm.
1.  **Start**: Place a "Miner" at the center of a grid full of walls.
2.  **Walk**: The miner moves in a random direction (North, South, East, West).
3.  **Dig**: Every cell the miner visits becomes a "Floor."
4.  **Repeat**: After 500 steps, you have a natural-looking cave system.
5.  **Clean-up**: We ensure that every floor is reachable from every other floor using a **Breadth-First Search (BFS)**.

---

## 5. Level Design Patterns in 3D

When building a 3D dungeon, you must think about **Verticality** and **Occlusion**.

### 5.1 Verticality
-   Instead of one floor, the `DungeonLayout` supports multiple layers.
-   **Logic**: We use "Stairs" nodes. When a player enters a stairs node, we move them up or down on the Y-axis and change the active dungeon layer.

### 5.2 Occlusion & Performance
-   We don't draw the whole dungeon at once. We only draw the room the player is in and the rooms immediately connected to it. 
-   This is called **Portal Culling**.

## 6. Creating a New Item / Entity

To add a "Gold Coin" to the game:
1.  **Load Mesh**: `asset_manager.load_mesh("coin.gltf")`.
2.  **Define Logic**: Create an `Entity` struct with a `on_interact` callback.
3.  **Attach to Scene**: Create a `SceneNode` for the coin and place it on a floor tile.
4.  **Collision**: Add the coin's position to the `GameState`'s interaction list.

## 7. Student Exercises (Learning Exercises)

1.  **Exercise: Third-Person Camera**: Modify the camera logic to follow the player from behind and above, rather than being inside their head.
2.  **Exercise: Procedural Loot**: Modify the dungeon generator to place a "Chest" entity at every dead-end of the cave.
3.  **Exercise: Fog of War**: Create a system where tiles are black (unrendered) until the player's light source touches them.
4.  **Exercise: Enemy AI**: Implement a simple "Patrol" state machine where an enemy walks between two points and starts "Chasing" if the player gets too close.

---

## 8. Concepts for Students
-   **Game State vs. Engine State**: The app manages "Why" things move; the engine manages "How" they are drawn.
-   **The Game Loop Pattern**: Initialize -> Input -> Update -> Render.
-   **Resource Management**: Notice how the app doesn't load textures itself; it asks the `AssetManager` for a `Handle`.

---

## 9. Troubleshooting the App
-   **"The player fell through the floor"**: Check if your `eye_height` is set correctly.
-   **"The game is lagging"**: Are you creating new `SceneNodes` every frame?
-   **"I can't see anything"**: Is your `PointLight` intensity too low?
