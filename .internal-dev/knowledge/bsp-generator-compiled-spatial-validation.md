# Key Takeaways

- Quake world brushes are additive. A corridor shell overlapping a complete room-wall brush does **not** carve a doorway; an "opening brush" is also solid. Model connected clear space first, then emit only boundary solids or split each wall around an omitted aperture.
- Intent-graph reachability is not compiled-map reachability. The failed generator had a connected MST while compiled room centers, portals, and point entities were solid. Corpus validation must load the compiled BSP and query representative room, entity, corridor, portal-throat, and junction witnesses.
- A 64-unit corridor needs a complete 64×64 endpoint square at turns/intersections. A closure centered on an L/T/X node can preserve line connectivity while stealing player-hull clearance. Keep posts in outer wall-thickness quadrants and test more than the exact center.
- Routes offset from room walls for obstacle clearance must add explicit normal approach legs back to the actual wall portal. Otherwise the emitted corridor ends outside the room shell and the graph is only logically connected.
- Enhanced multi-layer emission must retain a cell set per route and union only routes with the same vertical span. A global projected-XY `Cell -> CorridorCell` map lets an upper route overwrite a lower route and lets unrelated projected routes cut each other's room walls.
- A claimed socket is not a materialized portal unless routing starts at a reserved exterior approach cell. Routing directly from the wall anchor can choose an interior start cell, consume the socket, traverse the endpoint room, and exit elsewhere while emission still cuts the claimed wall. Route intent must include the normal wall-to-exterior leg and its 64-unit envelope.
- Odd-quantum room spans place semantic socket midpoints eight units off the construction grid. Derive one snapped four-cell portal descriptor and share it between the room wall mask, connector wall mask, and throat slabs; independently quantizing bounds creates an eight-unit leak slit.
- In stacked-room fixtures, omit an aperture only from the room wall that geometrically touches the transition shell. Omitting the opposite wall exposes the room directly to the outside flood, while omitting an entire touching wall leaves every span not covered by the narrower transition shell unsealed. A stacked pair that enters and exits on the same side needs separate lower/upper apertures and a stairwell shell spanning through the upper ceiling; a U-shaped two-lane stair provides direct approaches to both apertures.
- For Enhanced straight stairs, treat tread columns, host floor masks, host ceiling masks, and connector shells as one ownership partition. Emit each authoritative tread box once; omit its XY footprint from the host floor; omit the complete 192-unit run from the inter-layer slab so no overhang edge crosses the visible flight; and join the 176..192 exit to a supported upper connector landing through a full 64-unit crest throat. A warning-free nominal compile does not replace direct Type A/Type B solid/non-solid and full standing-height witnesses.
- `info_player_start` uses an eye/origin point, not floor elevation. With a 16-unit floor slab and a 24-unit hull-bottom/eye offset, the safe origin Z is `floor + 16 + 24`. Enhanced spawns belong at the center of the canonical 64×64 lower stair landing, not at a random point-clear room cell: reserve the 16-unit hull radius plus a real safety margin from both landing sides and tread solids, emit a cardinal `angle` toward the stair opening, query the exact authored origin (do not add another 40 units), and prove the compiled player hull is not start-solid. Room lights should use the clear-volume midpoint, not a slab boundary.
- ericw-tools can exit successfully while reporting fatal-for-publication authoring warnings, including missing miptex names and `No entities in empty space -- no filling performed`. Treat `WARNING:` and skipped-fill phrases as hard compiler-boundary failures.
- Compiler-helper `skip` still needs a real miptex in the source WAD. It should have no visible-material PBR companions. Never use an ad-hoc placeholder such as `generator_brick` unless the WAD actually contains it.
- For MCP queries, convert Quake `(x, y, z)` to engine meters as `(x, z, -y) * 0.0254`. Keep witness points inside clear-cell interiors rather than exactly on brush planes.
- A useful visual proof starts at the generated spawn/room center at eye height and looks down a known portal route. The seed-0 room/corridor captures show successive arch openings and baked-light gradients. Do not place the default MCP camera at the BSP bounds center: disconnected room layouts can leave that point in exterior void even when the compiled dungeon is sealed. Generated spawn origins already encode eye height, so do not add a second vertical offset; validate every semantic camera origin against compiled BSP contents before capture.
- BSP headless validation with `/tmp` BSP/LIT inputs can enter unrelated-root direct-import staging and hit GitHub #65 (`u128::to_le_bytes()` copied into an 8-byte slice). Until that runtime defect is fixed, preserve exact artifact hashes, copy the artifacts under a repo-relative `.internal-dev/captures/` path, and rerun the same strict capture there. This is a path-staging workaround only; it must not be used to excuse a generator/compiler/renderer failure.
- A frozen corpus must execute each declared seed/configuration pair exactly. Phase 09 Enhanced v2 validation found a fallback helper that replaced failed declared seeds while retaining their corpus names and reported a false 12/12 pass. Fail the entry instead, record the declared seed in evidence, and repair generation or obtain owner approval before changing the corpus.
- Keep room role surfaces explicit when visual acceptance requires one floor/ceiling/four-wall construction per room. A corridor-only open-cell union still handles turns and intersections; subtract both normal portal intervals and any routed endpoint-footprint wall cells so a 64×64 turn beside an endpoint-room corner remains non-solid after compilation.
- Do not infer runtime-budget compliance from a functional compiler corpus. Face/entity counts say nothing about parse/extract/upload/submission/memory/reload timings. The final nominal M1 seed 0 reports 183 render batches against the frozen `< 100` ceiling; the missing harnesses and contradicted batch claim are tracked by GitHub #57.
- In a shared working tree, a concurrent edit to the `bsp` dependency while `bsp_generator` tests are running can leave Rust doctests with `E0460` (mixed dependency metadata). Confirm source timestamps/processes, wait for the edit to stabilize, then rerun; do not misclassify that transient artifact mismatch as a generator regression.
- Package- or workspace-wide formatting can fail on unrelated concurrent or pre-existing files outside the patch. Record that result separately and run `rustfmt --check` on the changed generator files for a scoped formatting claim.
- A synthetic `BspWorld` may prove the `bsp::point_contents` traversal pipeline when small-map compiler runs are unstable, but it cannot qualify a source fixture, compiler profile, strict reload, BSP/LIT artifact, or collision witness. Keep the synthetic query result and compiler status as separate claim rows; never report a compiler-failed fixture as `PASS` merely because its synthetic query passed. A bounded compiler runner requires concurrent stdout/stderr drains, one combined output ceiling, process-group termination, and joined reader cleanup—blocking pipe reads inside a polling loop do not enforce a timeout.
- For the Enhanced v3 focused compiler fixtures, replacing 6–12-brush minimal shells with correctly wound 73–75-brush sealed maps avoided the pinned ericw-tools small-map hull crash. The expanded pointed portal, segmented portal, 45-degree shell, and grounded assembly all completed warning-free `qbsp -> vis -> light`, produced BSP2/QLIT v1 artifacts, strict-reloaded with zero diagnostics, and passed compiler-world contents witnesses. Retain the tool-limitation row anyway: a future signal exit during hull computation remains fixture `FAIL`, never permission to synthesize a compiler PASS.
- A focused segmented portal can be sealed while its integrated room/corridor interface still leaks. The production crown's 32-unit Z=112–128 centre recess sat above a corridor roof ending at Z=112. Preserve the visual recess in the wall depth, but terminate it with a one-quantum exterior cap at the interface; then compile the actual non-default package with warning rejection enabled. Source throat assertions alone do not prove exterior flood closure.
- The dense budget fixture needs the same compiler-safe structural density independently of semantic source estimates. The repaired hand-authored Rich fixture combines qualified portal and grounded-assembly structures into 160 brushes across lower floor 0 and upper floor 192; it compiles as a face-visible M2 artifact. Budget tests must panic on unavailable tools or any compiler failure instead of returning after writing zero measurements. Measure renderer static batches from `bsp::extract(...).render_batches`, not `world.models`, and keep source brush/side counts separate from strict-loaded faces, unique planes, nodes, leaves, clipnodes, and lightmap bytes.

# Engine Relevance

These rules apply whenever project-authored `.map` geometry is emitted from semantic topology. Validation must cross the compiler boundary because qbsp union/fill behavior, clip contents, miptex resolution, and renderer batching are not represented by the source intent graph alone. The preferred acceptance chain is deterministic generation → warning-free qbsp/vis/light → strict BSP reload → point-content witnesses → renderer/MCP capture, with runtime batch budgets measured separately.
