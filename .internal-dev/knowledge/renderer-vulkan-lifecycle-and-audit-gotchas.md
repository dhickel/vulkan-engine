## Key Takeaways

- Do not infer complete Vulkan cleanup from the size of `VkRenderCore::drop`. A Phase 05 GPU teardown audit found omitted cache, skybox-descriptor, image-view, host-pool, semaphore, and worker-thread cleanup. These paths are now explicitly destroyed, but future resource additions still need an ownership inventory and an actual drop-time GPU test.
- `VkDestroyable` existence does not prove invocation or unique ownership. Pipeline/layout teardown must deduplicate handles shared by opaque/alpha pipeline pairs before destruction; simply calling every nested `destroy` can trade leaks for double-destroys.
- The default graph does group geometry by pipeline and sorts blended objects back-to-front. Older claims that no draw sorting exists are stale.
- Present failures are not wholly ignored: any `queue_present` error sets `resize_requested`; however, the exact error (including device loss versus out-of-date/suboptimal) is discarded.
- Headless mode previously entered `ImguiPass` without an ImGui context and left an unbalanced dynamic-rendering region. Pass planning now skips that region when no context exists; preserve this ordering if the pass changes.
- Resetting a frame fence before command recording makes every early return after reset responsible for a submit or another way to restore signaled state. Frame transactions now drain post-acquire failures; new early-return paths must preserve the same invariant.
- A fence-only pre-submit fix is incomplete after windowed image acquisition. The image-available binary semaphore may already be signaled and a swapchain image acquired; a recoverable abort must also consume/release that synchronization and image state (for example, with a valid release submit/present) before reusing the slot.
- Calling `vkCreateSwapchainKHR` with non-null `oldSwapchain` retires the old swapchain even if creation fails. Preflight failures before the call may preserve old state; once the call begins, rollback may not render through the old handle or pass it again as a non-retired `oldSwapchain`.
- Alignment is allocation spacing, not source object size. Copying `next_multiple_of(alignment)` bytes from a stack struct over-reads the source; copy only `size_of::<T>()` and initialize destination padding separately.
- Raw material pointers are only valid while their cache storage cannot move or mutate. The gate removed this hazard: bucket resolution now copies `CopiedMaterialDrawRecord` while the texture-cache guard is held, and `RenderObject` retains only that by-value record. Preserve this boundary when adding draw-time material fields.
- `VkSubAllocator` primary/extra buffer IDs are currently inconsistent with vector indexing. Any fix needs one explicit mapping and property tests for overflow allocation, deallocation, batching, and free-list coalescing.
- Scene persistence currently validates fields it does not preserve (collision, visibility, prefab, audio and parts of light identity/parenting). Treat validation success as schema acceptance, not round-trip support.
- A `VmaDeviceMemoryBlock::Destroy` assertion reported as “renderer teardown” can originate from constructor rollback before `VkRenderCore` exists. Confirm with a native backtrace. In the Phase 1 failure, the default environment import returned an error after staged guards had committed, leaving 15 VMA allocations live: nine frame images, two host staging buffers, three cache suballocator buffers, and the default joint buffer.
- Keep all VMA-owning staged guards alive through the last fallible initialization step. Host staging buffers need a transfer guard because `VkTransfer` and `VkHostBuffer` use explicit `VkDestroyable` cleanup rather than Rust `Drop`.
- `VkHostBuffer::destroy` owns its buffer, two fences, semaphore, and both command pools. Older test fixtures that called `destroy` and then destroyed pools/semaphores again caused libc double-free aborts and obscured VMA validation.
- Mesh and texture host buffers must receive independently created graphics and transfer pool handles. Multiple owning wrappers around command buffers from one shared pool are not independent owners.
- Descriptor-layout cache entries may intentionally alias one Vulkan handle. In particular, skybox, irradiance, prefilter, and equirect filtering use one fragment-image descriptor layout. Teardown must deduplicate raw handles and destroy each unique layout once; iterating the fixed type-indexed array directly causes repeated `vkDestroyDescriptorSetLayout` calls.
- A VMA image destroy does not destroy an independently created `VkImageView`. Helpers that consume `VkImageAlloc` must take the logical device and follow the type's owner path (`image_view` first, then VMA image/allocation). The six leaked views in the Phase 1 gate were the six default texture views, not frame present/draw/depth targets.
- An async upload worker can hold a mesh or texture cache mutex while waiting on its `CountdownLatch`. The render thread must continue pumping transfers without blocking on that same cache. Use non-blocking cache finalization (`try_lock`) and, for bounded headless examples, finish deferred upload through the explicit asset pump before entering render-time cache lookups.
- Equal transfer and graphics queue-family indices are not an ownership transfer. Record the transition once with queue families ignored. Emitting both a release and acquire transition in one family produces stale-old-layout and unsupported stage/access validation errors; only distinct families use matching release/acquire barriers.
- Renderer default assets use workspace-root-relative paths. The Phase 05 GPU smoke parent therefore launches its isolated worker with the workspace root as `current_dir`; running the worker from the renderer package directory reproduces misleading missing-asset failures.
- Ash `queue_present` returns `Ok(true)` for a suboptimal presentation; treating every `Ok(_)` as fully presented loses `PresentedSuboptimal`. Preserve acquire's suboptimal boolean too, and distinguish out-of-date (`SubmittedNotPresented`) from suboptimal presentation.
- A renderer panic can be caught by host code even when the renderer no longer catches it internally. Use an unwind-aware poison guard around backend operations so the next backend operation returns `BackendPoisoned`; also poison after terminal Vulkan errors while returning the original typed error on the first failure.
- Frame-fence reset occurs only after successful image acquisition. Once reset, any recording failure must replace partial commands with a valid drain recording, submit it so the fence is signaled, and, for windowed acquisition, present it so both binary semaphores and the acquired image are retired. Failure-injection tests encode this state-machine contract.
- `CompletedFrameSlot` has two independent identities: the descriptor-reset epoch expected by the per-slot allocator and the last successful submitted serial proved complete by the fence. Replacing the former with the latter makes descriptor cleanup reject valid frames; keep both in the token.
- Submission serial publication belongs after successful `queue_submit2`. Reserving a candidate before the call is useful for draw-reference marking, but advancing the counter or stamping the frame slot before success fabricates a completable serial on submit failure.
- Generation exhaustion must be checked before replacing a live cache entry with a tombstone. A `checked_add` performed after `mem::replace` can return an error while dropping the payload that the still-logically-live handle owned.
- Do not perform ad-hoc `VK_ERROR_DEVICE_LOST` string matching at the public facade. Until every core helper returns one typed backend error, centralize legacy message classification inside the Vulkan wrapper (including the exact `ERROR_DEVICE_LOST` token), produce an internal device-loss variant there, and map that variant directly to `RendererError::DeviceLost`.
- A same-process GPU assertion can report success before `Drop` aborts the process. Run teardown-sensitive smoke work in an isolated child, assert its exit status in the parent, and inspect captured validation diagnostics. Decode the PNG rather than trusting its extension or byte count.
- Module-wide `allow(dead_code)` can turn a zero-warning build into false evidence. `RUSTFLAGS='--force-warn dead-code'` exposed the hidden inventory during Phase 05; remove obsolete internals and reserve reasoned allowances for exact diagnostic/capability items or per-example shared helpers.
- `cargo test -- --ignored` also runs Rustdoc blocks marked `ignore`. Illustrative snippets with placeholder handles should use `text` fences, not ignored Rust code, when the ignored test suite is an acceptance command.
- Taking a pending environment source out of `EnvironmentCache` before GPU upload is transactional state. Clone/restore it on upload or conversion failure so a transient GPU error does not silently replace retryable source data with an empty sentinel.
- Renaming a rendergraph field from `renderer` to `recording` does not narrow access if its type remains `&mut VkRenderCore`. Likewise, raw-pointer context wrappers without lifetime ties can create multiple safe-looking mutable aliases. The Phase 05 repair uses ordinary lifetime-bound field bundles for every pass and confines the only raw pointer to the current `VkFrame`; the dispatcher intentionally cannot reach `presentation`.
- Compiling a vertex-buffer bind does not prove an instancing ABI exists. The pipeline's vertex-input state and checked-in shader must both consume the instance binding; an unused local `VkVertexInputBindingDescription` plus `cmd_bind_vertex_buffers` leaves the legacy shader unaware of instance transforms. Require structural shader/pipeline evidence and an enabled headless capture, not only Rust unit tests.
- Vulkan constructors that allocate one owning image plus several custom views need rollback for every intermediate failure, not only the first allocation and normal teardown. CSM setup must destroy the partial frame's custom array/layer views, its VMA-owned image/default view, and every previously completed frame when later view or sampler creation fails.
- Failure to bind a present target after successful swapchain acquisition is not a resize skip: the acquire semaphore may already be signaled and the image acquired. If no valid target exists to record a drain, return a terminal backend error without rewinding the slot; backend poisoning and renderer teardown/recreation prevent synchronization reuse.
- A non-zero winit resize request can still produce a zero extent after Vulkan surface-capability selection during minimize/focus/compositor transitions. Check the selected plan extent before retiring the current generation or invoking swapchain creation. Keep the resize pending and return the retryable resize error surface while the current generation is still intact. Empty format/present-mode sets can be deferred the same way; capability-query failures, compatibility violations, and post-retirement failures remain terminal.
- Device-loss cleanup needs one core-owned terminal flag, not scattered best-effort checks. Mark it at the first typed/message-classified `ERROR_DEVICE_LOST`, avoid even immediate fence/temporary-image destruction on the failing environment path, and have `VkRenderCore::drop` skip all Vulkan/VMA calls. Fields with Vulkan-calling `Drop` implementations (currently the ImGui renderer) must be explicitly forgotten in this path; `ManuallyDrop` already protects the data cache and allocator. Environment generation must publish maps only after both targets succeed and record the handle in `environment_failures` on any failure.
- Environment face/mip log lines are emitted while commands are recorded, before queue submission. A device loss immediately after `face: 5, mip: 9` therefore identifies the end of CPU recording, not necessarily a tiny-mip shader fault. The renderer's all-mips submission was latent older behavior; voxel-demo commit `6bb56653` made the 4096x2048 indoor EXR the default launch environment and exposed the expensive path on every launch. Keep the 256px/nine-mip prefilter cap and submit each prefilter mip as its own command-buffer/fence batch, waiting before command-buffer reuse. Preserve the destination cubemap in `TRANSFER_DST_OPTIMAL` between batches; perform its initial transition only in the first batch and its final `SHADER_READ_ONLY_OPTIMAL` transition only in the last. The exact voxel-demo release smoke completed both default and explicit-environment nine-batch sequences and five captures with no device-loss diagnostics.
- In feature-gated renderer code, `cfg!(feature = "...")` does not remove references to names that exist only behind `#[cfg(feature = "...")]`. Use matching `#[cfg]` blocks for local booleans, imports, parameters, tests, and call sites. A cached/default check can miss this until a forced rebuild; include `RUSTFLAGS="--force-warn dead-code" cargo check -p dungeon_dogfood` or a clean no-feature renderer check when validating default-feature compileability.
- `VkPresent::replace_present_images` must clear the active frame reservation but keep `frame_epoch` monotonic. Per-frame descriptor allocators retain `last_reset_epoch` across swapchain rebuilds, so resetting the epoch to zero can make the next valid cleanup token look stale and reject descriptor pool reset.
- `vkFreeDescriptorSets` must be called with the exact pool that allocated the set; do not probe every tracked pool or assume wrong-pool frees are ignored. Track descriptor-set owner pools at allocation time when individual frees are needed.
- Texture retirement must not destroy sampler handles returned by `VkSamplerCache`. The sampler cache deduplicates and owns those handles; texture retirement owns the image/view/VMA allocation, while sampler cache teardown destroys samplers exactly once.
- Phase 06 validation exposed an evidence trap: `cargo test -p renderer` must be run unfiltered and should report 400+ renderer tests. A report of roughly 33 passing tests is a filtered/incomplete run, not full renderer validation. Incremental cargo cache can also make an early validation command appear green before touched dependencies force a real rebuild; rerun required checks after edits and treat later compile failures as authoritative. When adding image-state tracking, test subresource lookup directly: a full-image registration should answer mip/layer range queries, dropped frame overlays must not mutate committed state, and same-family queue-family indices must be `QUEUE_FAMILY_IGNORED` for buffer/image barriers.
- Phase 07 validation tightened the command-buffer indexing gate: a literal `rg "buffers\\[0\\]" src/renderer/src` is used as evidence and should return only `VkCommandPool::primary()`. Non-command-buffer names such as `extra_buffers` can still trip that literal gate, so write tests/docs without the bracketed literal unless they intentionally cover `VkCommandPool::primary()`.
- `TextureCache::destroy` is often called while `VkRenderCore::drop` already holds the allocator lock. Pending uploaded image teardown must use the allocator reference passed into `destroy`, not a helper that re-locks the same `Arc<Mutex<Allocator>>`.
- BSP retirement has the same non-reentrant allocator hazard: `reap_bsp_retirement` must acquire `mesh_cache → texture_cache → bsp_surface_cache → allocator`, remove queue records only after all locks succeed, and deallocate texture images with the held allocator guard. Calling `TextureCache::deallocate_texture` while holding that guard self-deadlocks. After successful `device_wait_idle`, `VkRenderCore::drop` must reap BSP closures through `latest_submitted_serial` before `VkDataCache`/VMA teardown; device-loss abandonment must skip this path.
- Asset upload backpressure must account for the render/main thread pumping transfer completion. A fixed small idle-poll count can fail while uploads are healthy; use a duration-bound wait, detect explicit `UploadBatchStatus::Failed`, and yield between polls.
- Shadow maps bound for scene sampling need explicit per-frame image-state registration and pass-owned transitions even when no light or no draw occurs. Leave the current legacy/CSM shadow image in `SHADER_READ_ONLY_OPTIMAL` before lighting samples it, and transition through tracked overlay state before depth attachment use.
- Validation-sensitive ignored GPU smoke tests should isolate child process teardown, run with `VK_LAYER_KHRONOS_validation` when available, and reject stale scene assertions that no longer match canonical derived bounds/deformation behavior.
- Environment-prep lock-poison hardening needs semantic review beyond replacing `expect`: passing `&*allocator.lock()?` into upload helpers can hold the allocator mutex through internal `device_wait_idle`, and cleanup-path `?` can replace the primary upload/generation error. Lock only around VMA operations and append cleanup failures to the primary error.

## Engine Relevance

These facts affect renderer safety reviews, Vulkan resource inventories, swapchain/frame error recovery, allocator changes, headless capture validation, and scene persistence claims. They should be rechecked after lifecycle or allocator fixes rather than copied indefinitely.

- Swapchain lifecycle is modeled as an explicit state machine (`vk_swapchain.rs`) with four legal states: `Nascent`, `Current`, `Retired`, `Absent`. Resize requests are coalesced to the latest non-zero extent. The irreversible boundary is calling `vkCreateSwapchainKHR` with non-null `oldSwapchain`: once that call is made, the old generation is permanently retired — never restored, never rendered through, never passed again as `oldSwapchain`. Present image views must be destroyed before the owning swapchain handle.
- Acquire and present Vulkan results are classified without string parsing using `AcquireClass` and `PresentClass` enums. `NOT_READY`/`TIMEOUT` are retry, `ERROR_OUT_OF_DATE_KHR`/`SUBOPTIMAL_KHR` are rebuild signals, `ERROR_SURFACE_LOST_KHR` is a distinct terminal internal class (different from `ERROR_DEVICE_LOST`), and other errors are `Fatal`. Present results distinguish `Ok(false)` presented from `Ok(true)` suboptimal.
- Exhausting a bounded `NOT_READY`/`TIMEOUT` acquire budget must skip only that frame. Converting transient unavailability into a resize request deadlocks caller-view loops that correctly wait while resize is pending, especially when the window extent never changed. Keep a practical per-attempt timeout for compositor scheduling, return a distinct transient outcome, and reserve resize requests for structural out-of-date/suboptimal results.
- `RebuildClass` captures the distinct failure modes: `FatalBeforeCreate` (all preflight passed, old not yet retired), `FatalAfterOldRetired` (old generation retired but new creation or dependent resources failed), `DeferredZeroExtent` (zero-size request deferred), `Installed`, `SurfaceLost`, and `DeviceLost`.
- The `SwapchainOwner` is the sole authority for state transitions. It stores pending resize requests separately from installed ones so a newer concurrent request remains pending after a rebuild installs. Zero-size events must also remain pending; dropping them makes minimize/restore state indistinguishable from no resize.
- `SwapchainOwner` must be the sole owner of window-system present views. `VkPresent` may reference the handles but must not independently destroy them. Cloning raw view handles into two destroying containers creates a teardown double-destroy even though Rust values were cloned safely.
- A successful swapchain creation followed by image-query failure still owns a real handle and must destroy it. Likewise, an image-view creation loop must destroy its successful prefix when a later view fails.
- A replacement's retired old handle remains alive until all replacement views are valid and the new generation/presentation references commit. Retirement forbids use; it does not require premature destruction.
- `device_wait_idle` remains in `rebuild_swapchain` as a pre-retirement drain, but state-machine tests must not depend on it as a substitute for ownership modeling.

### 2026-07-22 audit follow-up

- Reconfirmed that `VkSubAllocator` primary/extra buffer IDs and overflow ownership need an explicit, tested mapping: the first extra buffer must not use ID zero, and every successfully allocated overflow buffer must be committed to an owning collection before its `VkSubAlloc` records escape. Multi-batch uploads must advance by the checked aligned stride, never a reset batch counter. See `.internal-dev/reviews/2026-07-22-renderer-vulkan-rendergraph-review.md` and GitHub issue #53.
- Queue-family ownership transfers must be conditional on differing family indices for buffers as well as images. Device queue-create infos must coalesce roles sharing a family; one queue family may appear only once in `VkDeviceCreateInfo`.

## 2026-07-22 Data-layer review additions

- Mesh fence-aware retirement does not by itself make the asset pipeline GPU-safe. `TextureCache::deallocate_texture` and `deallocate_materials` can immediately destroy image allocations, descriptor-backed material metadata, and slots that submitted draw commands still reference. Any unload/hot-reload design must retire textures and materials on the same submit/fence serial model and must not recursively destroy shared textures solely from material teardown.
- In `MeshCache::allocate`, index-storage partial-allocation rollback must always use `index_storage`, never `vertex_storage`. The two suballocators are independent ownership domains; cross-deallocation can corrupt free-list state.
- Phase 03 validation repaired several allocator/cache transaction gotchas: overflow `sub_buffer_index` is a monotonic owner id, not a vector index; successful overflow allocations must be returned in original request order (primary prefix before overflow suffix); material descriptor failure rollback must deallocate staged, current, and not-yet-staged metadata allocations; texture upload recording must destroy partial image allocations and reset host command buffers on record/setup failure.
- Assimp resources returned by `aiCreatePropertyStore` and `aiImportFileExWithProperties` require RAII release guards on every success and error path. Do not return references to an imported scene beyond its guard lifetime.
- Action-map release semantics must remember which bindings were activated. Matching a release against current modifiers leaves actions stuck when a modifier is released before the trigger; aggregating multiple active bindings is also required before clearing a shared action.
- `ScriptEngine`'s shared current-script/event buffer is not an evaluation transaction merely because each access uses a mutex. Concurrent `&self` evaluations require a whole-evaluation lock or per-invocation context to prevent event and identity cross-talk.

## 2026-07-22 Phase-10 closeout additions

- The authoritative 21-row finding ledger lives at `tests/remediation_ledger.rs` with human-readable companion at `docs/internal/17-safety-refactor-remediation-ledger.md`. Every phase-addressable finding from the original 33-item review has been resolved, partially resolved, or explicitly deferred.
- Scene saves use `StagedSceneFile`: reserve a randomly named temp sibling → write + fsync → atomic rename. Partial writes are never published. On Unix, the staged file is opened with `O_NOFOLLOW | O_CREAT | O_EXCL` to reject symlink-based path-injection. Do not substitute only timestamp/PID/counter naming when the contract requires random staging names.
- `engine_pack` scan/pack traversal uses `symlink_metadata` (never follows symlinks), per-entry canonicalization with root containment, and a visited `(dev, ino)` set for cycle detection.
- All asset registry and pack report output is serializer-backed (TOML/JSON via `serde`). Ad-hoc escape/ID sanitization helpers have been removed. Non-UTF-8 paths are rejected at the scan boundary.
- Pipeline cache construction uses transactional staging: build in a temp sibling, validate, then atomically rename. On failure the staging directory is removed and the prior cache (if any) is untouched.
