# Phase Reports

Workers should write concise phase reports here for orchestration and HTML email summaries:

- `phase-01-export-audit.md`
- `phase-02-example-contract.md`
- `phase-03-friction-hardening.md`
- `phase-04-final-docs-validation.md`

Each report should include:

- phase objective;
- files changed;
- user-visible outcome;
- validation commands run and result;
- residual risks;
- capture status, if applicable;
- recommended email summary bullets.

The main thread owns sending HTML email after every phase.
