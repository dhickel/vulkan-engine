# Configurable Voxel Cave Demo

`voxel_demo` is the workspace application for deterministic procedural cave generation, MC33 isosurface extraction, wall/floor PBR partitioning, headless capture, and an app-owned windowed editor/regeneration loop.

The crate is an application, not a reusable public library. Its supported user surface is the `voxel_demo` command line, complete `PresetDocument` TOML files, window controls, editor actions, and capture artifacts described here.

## Quick Start

```bash
# Legacy v1 route (no v2-only selector)
cargo run -p voxel_demo

# Configurable v2 built-in presets
cargo run -p voxel_demo -- --preset default
cargo run -p voxel_demo -- --preset cavernous --seed 77
cargo run -p voxel_demo -- --preset mazy --resolution 128
cargo run -p voxel_demo -- --preset tight

# Complete external v2 document
cargo run -p voxel_demo -- --config ./my-cave.toml

# Deterministic v2 headless captures
cargo run -p voxel_demo -- \
  --preset default \
  --seed 77 \
  --headless \
  --capture-dir .internal-dev/captures/voxel-demo-doc-example
```

Options use the separated form `--flag VALUE`; the app parser does not accept `--flag=VALUE`.

## v1 and v2 Route Selection

The original v1 path and its goldens remain intact.

- No arguments, or only shared legacy flags (`--seed`, `--resolution`, `--shell-thickness`, `--light-budget`, `--headless`, `--capture-dir`/`--capture_dir`, and `--env`), select v1.
- `--preset`, `--config`, `--regen-after-frames`, or any v2-only generator/classifier/UV override selects v2.
- A v2 invocation without `--preset` or `--config` starts from the embedded `default` document.
- A complete `1/1/1` external document dispatches back to the legacy generator after document validation. A complete `2/2/2` document uses the configurable v2 pipeline.
- v1 golden files under `apps/voxel_demo/test_data/goldens/` are not regenerated by the v2 workflow.

This distinction matters when comparing output: `cargo run -p voxel_demo` and `cargo run -p voxel_demo -- --preset default` intentionally use different generator/RNG versions.

## CLI Reference

The parser tracks whether each override was present. Omitted values stay inherited from the selected base document; they are not replaced with parser defaults.

### Base selection

| Flag | Behavior |
| --- | --- |
| `--preset <NAME>` | Load one embedded v2 preset: `default`, `cavernous`, `mazy`, or `tight`. |
| `--config <PATH>` | Load one complete strict TOML document. Relative paths try the process working directory first, then `apps/voxel_demo/`, then the workspace root; relative asset paths inside the document resolve from the selected document's directory. |
| `--help` | Print the command summary and exit successfully. |

`--preset` and `--config` are mutually exclusive. Every option may appear at most once; `--capture-dir` and `--capture_dir` count as the same option. This makes both `--config presets/default.toml` and `--config apps/voxel_demo/presets/default.toml` valid from the workspace root while preserving working-directory precedence for user configs.

### Generator, classifier, and UV overrides

| Flag | Type | v2 behavior |
| --- | --- | --- |
| `--seed <N>` | `u64` | Override the deterministic seed; zero is valid. |
| `--resolution <N>` | `u32` | Override the cubic lattice resolution; validation accepts `64`, `96`, or `128`. |
| `--shell-thickness <N>` | `u32` | Override the six-face solid-shell thickness; v2 requires at least one voxel and validates operation clearance. |
| `--cavern-count <N>` | `u32` | Number of sites, from 5 through 12. The first five retain stable semantic roles. |
| `--tunnel-count <N>` | `u32` | Number of unique spline edges; must support a connected tree and not exceed the site-pair count. |
| `--tunnel-radius-min <F>` / `--tunnel-radius-max <F>` | `f32` | Positive ordered tunnel-radius range. |
| `--cavern-radius-min <F>` / `--cavern-radius-max <F>` | `f32` | Positive ordered cavern-radius range. |
| `--spline-tension <F>` | `f32` | Validated in `[0, 1]` and included in geometry identity. |
| `--roughness <F>` | `f32` | Non-negative surface displacement amplitude. |
| `--maze-density <F>` | `f32` | Fraction in `[0, 1]` used by the versioned maze-link count rule. |
| `--maze-twistiness <F>` | `f32` | Turn weighting in `[0, 1]` for deterministic maze search. |
| `--maze-radius <F>` | `f32` | Positive maze-carve radius. |
| `--maze-retries <N>` | `u32` | Positive bounded retry count. |
| `--maze-search-budget <N>` | `u32` | Positive global generation search budget. Checked products reject excessive work before generation. |
| `--floor-threshold <F>` | `f32` | World-space geometric-normal Y threshold in `[0, 1]`: `normal.y >= threshold` is floor. |
| `--wall-uv-scale <F>` / `--floor-uv-scale <F>` | `f32` | Positive per-partition UV multipliers. |

All floating-point inputs must be finite. Validation also checks version combinations, topology feasibility, interior dimensions, radius ordering, allocation estimates, MC33 worst-case capacity, and maze work using checked arithmetic. Invalid input exits nonzero before renderer initialization.

### Runtime-only options

| Flag | Default | Behavior |
| --- | --- | --- |
| `--light-budget <N>` | `9` | Validate a runtime budget in `9..=16`. It is excluded from documents, saves, and identities. The current package derives five mandatory site lights and up to four best-effort midpoint lights. |
| `--headless` | off | Use one-shot headless generation/upload/capture. Headless v2 creates no editor or regeneration controller. |
| `--capture-dir <PATH>` / `--capture_dir <PATH>` | generated run directory | Select the v1/v2 headless capture root. Both spellings are equivalent. |
| `--env <PATH>` | `apps/dungeon_dogfood/assets/sky_maps/indoor_4k.exr` | Select an IBL environment. A missing or failed environment falls back to the renderer default environment. |
| `--regen-after-frames <N>` | off | Select v2 and, in windowed mode, submit one seed+1000 regeneration when frame `N` is reached and no work is pending. It is a validation/debug trigger, not persisted configuration. |

There is no command-line save flag or campaign/debug-recording flag in the app parser. Save complete documents from the windowed editor. Unknown options are errors.

## Built-in Presets

The embedded bytes are the source files in `apps/voxel_demo/presets/`; tests assert that the embedded catalog and those files stay equal.

| Preset | Default resolution | Sites / spline edges | Maze style | Intended character |
| --- | ---: | ---: | --- | --- |
| `default` | 96³ | 7 / 9 | 0.15 density, moderate search | Balanced caverns, tunnels, and maze links. |
| `cavernous` | 96³ | 5 / 6 | 0.05 density | Large open caverns, broad tunnels, minimal maze enrichment. |
| `mazy` | 64³ | 9 / 14 | 0.18 density, high twist/search budget | Dense interconnected layout with more sites and links. |
| `tight` | 64³ | 5 / 5 | 0.20 density | Smaller passages, thick shell, and stronger roughness. |

Presets are complete documents, not partial overlays. CLI fields explicitly supplied after base selection override the corresponding generator fields only.

## `PresetDocument` TOML Contract

A document is strict and complete: unknown fields, duplicate fields, missing fields, unsupported version tuples, malformed references, and non-finite values are rejected. Supported version tuples are `1/1/1` and `2/2/2` for schema/generator/RNG respectively.

```toml
schema_version = 2
generator_version = 2
rng_version = 2

[generator]
seed = 0
resolution = 96
shell_thickness = 2
cavern_count = 7
tunnel_count = 9
tunnel_radius_min = 1.5
tunnel_radius_max = 3.0
cavern_radius_min = 4.0
cavern_radius_max = 8.0
spline_tension = 0.5
roughness = 0.3
maze_density = 0.15
maze_twistiness = 0.4
maze_radius = 1.2
maze_retries = 50
maze_search_budget = 30000
floor_threshold = 0.3
wall_uv_scale = 1.0
floor_uv_scale = 2.0

[materials.wall]
albedo = { type = "catalog", id = "kb3d/rock_wall_01" }
normal = { type = "catalog", id = "kb3d/rock_wall_01" }
roughness = { type = "catalog", id = "kb3d/rock_wall_01" }
ao = { type = "catalog", id = "kb3d/rock_wall_01" }
base_color_r = 0.8
base_color_g = 0.7
base_color_b = 0.6
roughness_factor = 1.0
metallic_factor = 0.0

[materials.floor]
albedo = { type = "catalog", id = "kb3d/rock_floor_01" }
normal = { type = "catalog", id = "kb3d/rock_floor_01" }
roughness = { type = "catalog", id = "kb3d/rock_floor_01" }
ao = { type = "catalog", id = "kb3d/rock_floor_01" }
base_color_r = 0.6
base_color_g = 0.55
base_color_b = 0.5
roughness_factor = 0.9
metallic_factor = 0.0
```

A seed above TOML's signed 64-bit range is written as a decimal string. Save normalizes `-0.0` to `0.0`. Catalog references remain catalog IDs. Filesystem references use:

```toml
albedo = { type = "filesystem", path = "textures/wall.png", non_portable = false }
```

Relative filesystem references require `non_portable = false` and resolve from the source document directory. Absolute references require `non_portable = true`. Canonical saves convert filesystem references to normalized absolute non-portable paths and then reload/validate the saved document. The current KB3D material uploader expects the known wall/floor catalog albedo IDs; arbitrary filesystem references can pass document resolution but are not a supported material-upload path.

Runtime fields (`light_budget`, headless mode, capture path, environment override, editor visibility, pending requests) never enter `PresetDocument` or saved TOML.

## Deterministic Identities

The v2 resolver computes two domain-separated SHA-256 identities from normalized typed values:

- `GeometryIdentity`: generator version, RNG version, seed, resolution, shell, site/tunnel shape fields, roughness, and maze fields.
- `SceneConfigIdentity`: the geometry digest plus floor classifier, resolved wall/floor asset references, material factors, UV scales, and the fixed lighting-policy description.

Raw TOML bytes, formatting, field order, source labels, editor state, capture/environment runtime choices, and `light_budget` do not affect either identity. Equivalent filesystem spellings are normalized before identity construction. Asset-content digests are reproduction/cache metadata and remain separate from semantic identities.

The editor displays active and draft scene-config identities so a valid draft can be compared with the currently presented cave before regeneration.

## v2 Generation and Rendering Pipeline

```text
PresetDocument + presence-aware CLI overrides
  → normalize, resolve references, validate, compute identities
  → named RNG streams and topology-first v2 generation
  → VoxelWorld density/material lattices
  → MC33 extraction and structural validation
  → geometric-normal wall/floor partition + independent UV scales
  → renderer-free CpuScenePackage
  → main-thread texture/material creation and procedural mesh upload
  → Scene + app-owned windowed loop, or one-shot headless capture
```

v2 retains five core roles in stable ID order: `spawn`, `junction`, `grand_cavern`, `shaft`, and `destination`. Additional sites receive deterministic auxiliary IDs. Spline construction first creates a connected semantic backbone, then deterministic extras. Maze routes are planned and reserve their complete carve footprint before any accepted maze route is carved; exhaustion returns a typed error without exposing a partially generated world.

The shell/interior calculation accounts for configured shell thickness, feature radius, roughness reach, and extraction margin. Carving stays within that operation-aware interior, after which all shell layers are enforced and verified.

MC33 produces one source mesh. The partitioner classifies each triangle from its consistently wound world-space geometric normal, assigns it exactly once to wall or floor, preserves source order/winding and non-UV attributes, applies the selected UV multiplier, and compacts vertices by first reference. Empty wall or floor partitions remain absent rather than uploading an empty mesh.

## PBR Material Policy

Wall and floor partitions use separate KB3D material bundles:

- `*_basecolor.png`: sRGB;
- `*_normal.png`: linear;
- separate `*_roughness.png`: linear, bound to `metallic_roughness_tex`; grayscale replication supplies the renderer's G-channel roughness sample;
- separate `*_ao.png`: linear, bound to `ao_tex`; the renderer samples AO from R;
- repeat wrapping and linear/mip filtering for all roles;
- metallic factor fixed to `0.0`;
- `_arm.png`, `_metallic.png`, and `_height.png` are not loaded.

The KB3D files are local-development assets. Redistribution and packaging approval are not established by this app; do not treat repository availability as a redistribution license.

## Windowed Controls and Editor

| Input | Action when editor is hidden |
| --- | --- |
| **W A S D** | Horizontal FPS movement. |
| **Mouse** | FPS look. |
| **Space** / **Left Shift** | Move up / down. |
| **F** | Toggle the app's noclip state/logging. The demo does not add collision. |
| **C** | Queue a renderer draw-target manual capture under a timestamped `captures/voxel-demo-*` directory. |
| **F1** or **F2** | Toggle the voxel editor. These keys are consumed before normal renderer/app routing. |

The v2 editor is visible by default. While registered, existing renderer imgui capture policy suppresses app camera/gameplay input; viewport click-through is not promised. Hiding unregisters the app UI callback and restores camera routing. Showing it queues synthetic releases for movement/capture hotkeys so held input does not remain latched.

Editor capabilities:

- replace the complete draft from any built-in preset;
- load a complete external config;
- edit every generator/classifier/UV field and all wall/floor material references/factors;
- validate inline and display active/draft identities;
- show request phase, active triangle/voxel counts, CPU stage timings, material-cache size, and retirement count;
- save a complete canonical snapshot;
- randomize only the draft seed using OS randomness;
- explicitly regenerate a valid draft;
- hide/unregister the editor.

Editing, loading, saving, or randomizing never implicitly regenerates. `Regenerate` and `Save` are disabled/rejected for an invalid or unresolvable draft.

The imgui callback performs no file I/O, OS randomness, worker launch, or renderer mutation. It enqueues owned `EditorCommand` snapshots into a bounded queue (32 commands); the event-loop owner drains and executes them after the callback borrow ends. Saving a snapshot does not erase newer edits made after that command was queued.

## Regeneration Semantics

Windowed v2 uses one `RegenerationState`:

1. Submitting a valid snapshot increments a monotonic request ID.
2. At most one CPU worker builds a renderer-free `CpuScenePackage`; one latest pending request replaces any older pending request.
3. A completed stale result is discarded. If a newer request exists, that latest snapshot is launched next.
4. Accepted CPU results return to the main thread. Texture/material creation, procedural uploads, light updates, and scene mutation never run on the worker.
5. A candidate cave node and optional wall/floor meshes are staged while the old cave remains active.
6. The request ID is checked before staging side effects and again before stable-light mutation.
7. Commit updates existing point-light IDs, removes the old cave node, and only then makes the candidate authoritative.
8. On a recoverable staging/light/node-removal failure, prior light descriptors are restored, the candidate is removed, candidate meshes are unloaded, and the old package remains active.
9. Detached old meshes are handed to the renderer's fence-aware mesh-unload path. App-owned material/texture bundles are protected by the material cache and a minimum three-frame retirement grace before unload attempts.

This is latest-wins request coalescing, not cancellation of a CPU thread already running and not asynchronous GPU upload. Upload and commit work can still produce a main-thread hitch.

## Headless Capture

v2 headless mode uses the same config resolution, validation, generator, MC33, partition, material, identity, light, and CPU-package pipeline as windowed mode. It intentionally does not construct the editor or regeneration state.

The app creates a 1920×1080 headless renderer, warms ten frames, then captures the five core-role viewpoints. Each viewpoint allows up to 20 render polls and writes:

- `cave_s<seed>_r<resolution>_<role>.png`;
- renderer sidecar `..._sidecar.json`;
- enriched app sidecar `..._enriched.json` with versions, seed/resolution, camera, identities, triangle/voxel/light counts, stage timings, and wall/floor references.

A config, generation, material, upload, or capture failure exits nonzero. Headless draw capture is deterministic rendering evidence; it is not evidence for real-window WSI behavior.
