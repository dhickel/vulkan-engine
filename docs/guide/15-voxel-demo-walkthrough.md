# 15 — Case Study: Voxel Demo

> Provenance: `G-15` — excerpts from `apps/voxel_demo/src/`; canonical source at [`apps/voxel_demo/`](../../apps/voxel_demo/)

This chapter walks through `voxel_demo` — the configurable procedural-cave application. It demonstrates strict TOML presets, deterministic v2 generation, MC33 isosurface extraction, wall/floor PBR partitioning, main-thread material upload, an imgui editor with command-queue architecture, latest-wins regeneration coalescing, and headless multi-viewpoint capture.

This chapter **leads with the v2 `--preset`/`--config` path**. The no-selector v1 route is retained for compatibility but is not the recommended starting point. See [v1 and v2 Route Selection](#v1-and-v2-route-selection) for the distinction.

> **Label**: This app is **not standalone**. It is a workspace member under `apps/voxel_demo/` and requires the root workspace to build. Use `cargo run -p voxel_demo`, never `cargo run --manifest-path`.

## Quick Start

```sh
# v2 built-in presets (recommended)
cargo run -p voxel_demo -- --preset default
cargo run -p voxel_demo -- --preset cavernous --seed 77
cargo run -p voxel_demo -- --preset mazy --resolution 128
cargo run -p voxel_demo -- --preset tight

# Complete external v2 TOML document
cargo run -p voxel_demo -- --config ./my-cave.toml

# Deterministic v2 headless captures
cargo run -p voxel_demo -- \
  --preset default \
  --seed 77 \
  --headless \
  --capture-dir .internal-dev/captures/voxel-demo-default-77
```

> **Important**: Options use space-separated form `--flag VALUE`. The app parser does not accept `--flag=VALUE`.

> Provenance: `G-15-QS` — commands from `docs/api/16-voxel-demo.md` quick-start section.

## v1 and v2 Route Selection

> Provenance: `G-15-ROUTE` — from [`apps/voxel_demo/src/cli.rs`](../../apps/voxel_demo/src/cli.rs) and `main.rs`

The parser selects the route based on which flags are present:

| Invocation Pattern | Route |
|---|---|
| No arguments, or only shared legacy flags (`--seed`, `--resolution`, `--shell-thickness`, `--light-budget`, `--headless`, `--capture-dir`, `--env`) | **v1** (compatibility) |
| `--preset`, `--config`, `--regen-after-frames`, or any v2-only generator/classifier/UV override | **v2** |
| v2 without `--preset` or `--config` | Uses embedded `default` preset |

This distinction matters: `cargo run -p voxel_demo` and `cargo run -p voxel_demo -- --preset default` intentionally use different generator/RNG versions.

v1 golden files under `apps/voxel_demo/test_data/goldens/` are not regenerated by the v2 workflow.

## Presets and Config Resolution

> Provenance: `G-15-CONFIG` — from [`apps/voxel_demo/src/config.rs`](../../apps/voxel_demo/src/config.rs) and `main.rs` `run_v2()`

### Resolution Order

`run_v2()` in `main.rs` follows a strict resolution pipeline:

1. **Base selection**: Exactly one base document is chosen from `--preset`, `--config`, or the embedded `default`.
2. **Normalization**: The base is normalized (canonical float representations, field ordering).
3. **Asset reference resolution**: All eight material references (wall/floor albedo, normal, roughness, AO) are resolved against the document's source directory and the known catalog IDs.
4. **CLI override application**: Only explicitly present CLI flags override the corresponding generator fields. Omitted flags leave the base value intact.
5. **Re-normalization**: The merged document is normalized again after overrides.
6. **Validation**: `validate_preset_document()` checks version tuples, topology feasibility, radius ordering, allocation estimates, MC33 worst-case capacity, and maze work budgets.
7. **Runtime validation**: `validate_runtime_light_budget()` checks `--light-budget` is in `9..=16`.
8. **Identity computation**: `GeometryIdentity` and `SceneConfigIdentity` are computed from the validated canonical typed values (not from raw bytes).

### Built-in Presets

The embedded bytes are the source files in [`apps/voxel_demo/presets/`](../../apps/voxel_demo/presets/); tests assert the embedded catalog matches those files.

| Preset | Default resolution | Sites / spline edges | Maze style | Character |
|--------|-------------------:|---------------------:|------------|-----------|
| `default` | 96³ | 7 / 9 | 0.15 density, moderate search | Balanced caverns, tunnels, and maze links |
| `cavernous` | 96³ | 5 / 6 | 0.05 density | Large open caverns, broad tunnels, minimal maze |
| `mazy` | 64³ | 9 / 14 | 0.18 density, high twist/search budget | Dense interconnected layout |
| `tight` | 64³ | 5 / 5 | 0.20 density | Smaller passages, thick shell, stronger roughness |

Presets are complete documents, not partial overlays.

## Identities

> Provenance: `G-15-IDENTITY` — from [`apps/voxel_demo/src/config.rs`](../../apps/voxel_demo/src/config.rs)

The v2 resolver computes two domain-separated SHA-256 identities:

- **`GeometryIdentity`**: generator version, RNG version, seed, resolution, shell, site/tunnel shape fields, roughness, and maze fields.
- **`SceneConfigIdentity`**: the geometry digest plus floor classifier, resolved wall/floor asset references, material factors, UV scales, and the fixed lighting-policy description.

Raw TOML bytes, formatting, field order, source labels, editor state, capture/environment runtime choices, and `light_budget` do not affect either identity. Equivalent filesystem spellings are normalized before identity construction.

The editor displays active and draft scene-config identities so a valid draft can be compared with the currently presented cave before regeneration.

## Named RNG Streams

> Provenance: `G-15-RNG` — from [`apps/voxel_demo/src/cave_gen/rng.rs`](../../apps/voxel_demo/src/cave_gen/rng.rs)

The v2 generator uses `PhaseTaggedRng` — a deterministic RNG that derives per-phase sub-streams from the master seed. Each generation phase (site placement, spline construction, maze planning, tunnel carving, noise application) gets a unique domain-separated stream. This ensures that changing one phase's algorithm does not alter the RNG output of unrelated phases, and that identical configs always produce identical geometry.

## v2 Generation and Rendering Pipeline

> Provenance: `G-15-PIPELINE` — from `main.rs`, `cave_gen/`, `meshers/`, `scene_package.rs`

```text
PresetDocument + presence-aware CLI overrides
  → normalize, resolve references, validate, compute identities
  → PhaseTaggedRng streams, topology-first v2 generation
  → VoxelWorld density/material lattices
  → MC33 extraction + structural validation
  → geometric-normal wall/floor partition + independent UV scales
  → renderer-free CpuScenePackage
  → main-thread texture/material creation + procedural mesh upload
  → Scene + app-owned windowed loop, or one-shot headless capture
```

### v2 Generation

Five core roles exist in stable ID order: `spawn`, `junction`, `grand_cavern`, `shaft`, and `destination`. Additional sites receive deterministic auxiliary IDs.

Spline construction first creates a connected semantic backbone, then deterministic extras. Maze routes are planned and reserve their complete carve footprint before any accepted maze route is carved; exhaustion returns a typed error without exposing a partially generated world.

The shell/interior calculation accounts for configured shell thickness, feature radius, roughness reach, and extraction margin. Carving stays within that operation-aware interior, after which all shell layers are enforced and verified.

### MC33 Wall/Floor Partition

MC33 produces one source mesh. The partitioner:

- Classifies each triangle from its consistently wound world-space geometric normal.
- Assigns it exactly once to wall (`normal.y < floor_threshold`) or floor (`normal.y >= floor_threshold`).
- Preserves source order, winding, and non-UV attributes.
- Applies the selected UV multiplier per partition.
- Compacts vertices by first reference.

Empty wall or floor partitions remain absent rather than uploading an empty mesh.

## PBR Materials

> Provenance: `G-15-MATERIALS` — from [`apps/voxel_demo/src/materials.rs`](../../apps/voxel_demo/src/materials.rs)

Wall and floor partitions use separate KB3D material bundles:

| Role | Source | Format | Binding |
|------|--------|--------|---------|
| Albedo | `*_basecolor.png` | sRGB | `base_color_tex` |
| Normal | `*_normal.png` | linear | `normal_tex` |
| Roughness | `*_roughness.png` | linear, R-channel | `metallic_roughness_tex` (G-channel replicated from R) |
| AO | `*_ao.png` | linear, R-channel | `ao_tex` |

All textures use repeat wrapping and linear/mip filtering. Metallic factor is fixed to `0.0`. `_arm.png`, `_metallic.png`, and `_height.png` are not loaded.

> **Note**: KB3D files are local-development assets. Redistribution and packaging approval are not established by this app.

## Main-Thread Upload

> Provenance: `G-15-UPLOAD` — from [`apps/voxel_demo/src/regeneration.rs`](../../apps/voxel_demo/src/regeneration.rs)

The CPU worker builds a renderer-free `CpuScenePackage` with raw vertex/index buffers and light descriptors. All GPU uploads happen on the main thread:

1. Texture creation via `MaterialCache` (deduplicates identical material configs).
2. `assets.upload_procedural_mesh()` for wall and floor partitions.
3. Scene node creation and mesh attachment.
4. Point light creation/update.

The worker thread never touches the renderer, asset manager, or scene.

## Editor and Command Queue

> Provenance: `G-15-EDITOR` — from [`apps/voxel_demo/src/editor.rs`](../../apps/voxel_demo/src/editor.rs)

The v2 editor is visible by default in windowed mode. While registered, existing renderer imgui capture policy suppresses app camera/gameplay input. Hiding unregisters the app UI callback and restores camera routing.

### Editor Capabilities

- Replace the complete draft from any built-in preset
- Load a complete external config
- Edit every generator/classifier/UV field and all wall/floor material references/factors
- Validate inline and display active/draft identities
- Show request phase, active triangle/voxel counts, CPU stage timings, material-cache size, and retirement count
- Save a complete canonical snapshot
- Randomize only the draft seed using OS randomness
- Explicitly regenerate a valid draft
- Hide/unregister the editor

Editing, loading, saving, or randomizing never implicitly regenerates. `Regenerate` and `Save` are disabled/rejected for an invalid or unresolvable draft.

### Command Queue

The imgui callback performs no file I/O, OS randomness, worker launch, or renderer mutation. It enqueues owned `EditorCommand` snapshots into a bounded queue (32 commands). The event-loop owner drains and executes them after the callback borrow ends. Saving a snapshot does not erase newer edits made after that command was queued.

Toggles:
- **F1** or **F2**: Toggle the voxel editor visibility.

## Regeneration Semantics

> Provenance: `G-15-REGEN` — from [`apps/voxel_demo/src/regeneration.rs`](../../apps/voxel_demo/src/regeneration.rs)

Windowed v2 uses one `RegenerationState`:

1. Submitting a valid snapshot increments a monotonic request ID.
2. At most one CPU worker builds a renderer-free `CpuScenePackage`.
3. One latest pending request replaces any older pending request (**latest-wins coalescing**).
4. A completed stale result is discarded. If a newer request exists, that latest snapshot is launched next.
5. Accepted CPU results return to the main thread. Texture/material creation, procedural uploads, light updates, and scene mutation never run on the worker.
6. A candidate cave node and optional wall/floor meshes are staged while the old cave remains active.
7. The request ID is checked before staging side effects and again before stable-light mutation.
8. **Commit**: Updates existing point-light IDs, removes the old cave node, and only then makes the candidate authoritative.
9. **Rollback**: On a recoverable staging/light/node-removal failure, prior light descriptors are restored, the candidate is removed, candidate meshes are unloaded, and the old package remains active.
10. Detached old meshes are handed to the renderer's fence-aware mesh-unload path.
11. App-owned material/texture bundles are protected by a minimum **three-frame retirement grace** before unload attempts.

This is latest-wins request coalescing, not cancellation of a CPU thread already running and not asynchronous GPU upload. Upload and commit work can still produce a main-thread hitch.

## Headless Viewpoints

> Provenance: `G-15-HEADLESS` — from `main.rs` headless section

v2 headless mode uses the same config resolution, validation, generator, MC33, partition, material, identity, light, and CPU-package pipeline as windowed mode. It intentionally does not construct the editor or regeneration state.

The app creates a 1920×1080 headless renderer, warms ten frames, then captures the five core-role viewpoints. Each viewpoint allows up to 20 render polls and writes:

- `cave_s<seed>_r<resolution>_<role>.png`
- renderer sidecar `..._sidecar.json`
- enriched app sidecar `..._enriched.json` with versions, seed/resolution, camera, identities, triangle/voxel/light counts, stage timings, and wall/floor references.

```sh
# Headless v2 capture with explicit seed
cargo run -p voxel_demo -- \
  --preset default --seed 77 --headless \
  --capture-dir .internal-dev/captures/voxel-demo-default-77
```

A config, generation, material, upload, or capture failure exits nonzero. Headless draw capture is deterministic rendering evidence; it is not evidence for real-window WSI behavior.
